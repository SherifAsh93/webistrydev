# نظام إدارة العملاء المحتملين

نظام لإدارة الشركة بالكامل: عدة مشاريع/فروع، كل مشروع له استمارة عملاء خاصة به (حقول وصورة وعنوان مختلفين)، وموظفو الشركة (قائمة واحدة مشتركة) يمكن تعيين أي منهم للعمل على أي مشروع. لوحة تحكم واحدة محمية بكلمة مرور تعطي المدير نظرة شاملة على كل المشاريع والموظفين وأدائهم.

## كيف يعمل النظام

1. المدير يفتح `/admin` ويسجّل الدخول بكلمة المرور (`ADMIN_PASSWORD`).
2. **نظرة عامة**: إحصائيات عامة (عدد المشاريع، الموظفين، العملاء)، وأداء كل موظف عبر كل المشاريع.
3. **الموظفين**: قائمة موظفي الشركة (مشتركة بين كل المشاريع) — إضافة وحذف فقط، بدون روابط هنا.
4. **المشاريع**: إنشاء مشروع جديد أو فتح مشروع موجود. داخل كل مشروع:
   - **تصميم الاستمارة**: عنوان الاستمارة والوصف والصورة والحقول (أي حقول يريدها المدير).
   - **الموظفين المعيّنين**: يعيّن المدير موظفين من قائمة الشركة للعمل على هذا المشروع تحديدًا، ولكل موظف معيّن زر "نسخ الرابط" ينسخ رابط فريد يحمل اسمه وهاتفه ومعرّفه.
   - **الطلبات**: كل عملاء هذا المشروع فقط، مع بحث وتعديل وحذف.
5. المدير يرسل رابط الموظف له عبر واتساب أو أي وسيلة؛ الموظف يرسله بدوره للعميل.
6. العميل يفتح الرابط، يملأ بياناته، ويضغط "إرسال" — بدون أي تسجيل دخول من جهة العميل أو الموظف.
7. البيانات تُحفظ تلقائياً مرتبطة بالموظف (لحساب أدائه في "نظرة عامة") والمشروع.

## الإعداد

### 1. المتطلبات

- Node.js 18+
- حساب [Supabase](https://supabase.com) مجاني

### 2. إعداد قاعدة البيانات

1. أنشئ مشروع جديد في Supabase.
2. افتح SQL Editor وشغّل محتوى الملف `supabase/schema.sql`.
3. من إعدادات المشروع (Project Settings → API) انسخ:
   - `Project URL`
   - `service_role` key (سرّي، لا تشاركه)

### 3. متغيرات البيئة

انسخ `.env.local.example` إلى `.env.local` وعبّئ القيم:

```bash
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
SUPABASE_SERVICE_ROLE_KEY=xxxxxxxx
ADMIN_PASSWORD=اختر-كلمة-مرور
```

> كل الاتصال بقاعدة البيانات يتم من الخادم (API routes) باستخدام مفتاح service role، ولا يصل المتصفح لقاعدة البيانات مباشرة أبداً. `/admin` وكل الـ API routes الإدارية محمية بكلمة مرور واحدة (`ADMIN_PASSWORD`) عبر `middleware.ts` — صفحة النموذج العام `/form` واستقبال الطلبات (`POST /api/leads`) فقط لا تحتاج كلمة مرور.

### 4. تشغيل المشروع محلياً

```bash
npm install
npm run dev
```

افتح [http://localhost:3000](http://localhost:3000) (يوجّهك مباشرة إلى `/admin`، وسيطلب كلمة المرور).

## النشر على Vercel

1. ادفع المشروع إلى مستودع GitHub.
2. من [Vercel](https://vercel.com/new) استورد المستودع.
3. أضف متغيرات البيئة نفسها (`NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `ADMIN_PASSWORD`) في إعدادات المشروع على Vercel لكل البيئات (Production/Preview/Development).
4. اضغط Deploy.

## البنية التقنية

- Next.js 14 (App Router) + TypeScript + Tailwind CSS
- Supabase (Postgres) — جداول `projects`، `employees` (مشتركة بين الشركة)، `project_employees` (تعيين موظف لمشروع)، `leads` (مرتبط بمشروع وبموظف)
- حماية بكلمة مرور عبر `src/middleware.ts` + كوكي httpOnly
- RTL بالكامل، خط Tajawal، تصميم يُناسب الجوال أولاً
